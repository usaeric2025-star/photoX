# Incident Postmortem: v2.12 Translation Tool Pollution & Safe Restoration

This document details the incident analysis, recovery, and institutional corrections following the inadvertent codebase pollution during translation updates.

---

## 🔍 1. Incident Root Cause Analysis

### The Scenario
During translation and localization cleanup in v2.12, helper functions utilizing a single-letter variable `t` for the standard translator callback clashed with object properties (e.g., `t.id`) and dynamic import strings.

### Key Factors:
1. **Ambiguous Variable Selection**: The widespread usage of the single-character variable `t` as a semantic abbreviation for `translate` made regex-based find-and-replace scripts extremely dangerous.
2. **Regex Limitations**: Textual replacement engines (such as regex, `sed`, or simple string searches) are context-unaware. They cannot distinguish between:
   - A function call: `t('key')`
   - An object/property accessor: `photoCard.t` / `t.id`
   - A type descriptor/generic signature: `<T>`
   - Spurius identifier matches inside text strings or JSX names.
3. **Cascading Failures**: When the expression `import('meta')` was corrupted because of a broad find-and-replace match on single characters, the TypeScript compilation broke and the dev server entered a failed state.

## 🛡️ 3. institutional Prevention & Structural Rule Enforcement

To eliminate similar regressions, we have anchored the following rules into `AGENTS.md` and the team's development lifecycle:

### A. Strict Prohibition of Single-Letter Semantic Variables
Except for established standard loop indices (e.g., `for (let i = 0; ...)`) and generic parameters (e.g., `<T>`), NO single-letter variables are allowed as key logic carriers.
- Use `translate` or `dict` instead of `t`.
- Use `photo` or `item` instead of `p`.
- Use `error` instead of `e`.

### B. Mandatory AST-Based Global Refactoring
- **Regex Bans**: All multi-file search-and-replace operations for identifiers and syntax structures are strictly banned from using regex or raw text tools.
- **AST Codemods**: Must use `jscodeshift` or `ts-morph` syntax parser-based codemods.
- **Idempotency**: All AST transformations must natively check for idempotency and protect JSX tags and properties.

### C. Local Sandbox Verification
- Any transformation scripts must first be validated inside sample files in a `/sandbox` directory before migrating any file within `/src`.
- Each iteration must run `npm run lint` and `npm run build` locally to guarantee green pipelines.
