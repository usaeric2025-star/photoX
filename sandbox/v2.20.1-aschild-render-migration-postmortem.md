# Postmortem: v2.20.1 asChild -> render prop Migration

## 🚨 故障現象
- 在 `GroupDetailView`, `PhotoLightbox`, `PhotoEditDrawer` 等組件中頻發 `t is not defined` 或 `translate is not a function` 運行時異常。
- 控制台出現大量 Base UI (Dialog / Portal) 的 `asChild` 屬性與 DOM 元素不匹配的警告，導致渲染層級丟失或動畫異常。

## 🔍 根因分析
1. **API 演進斷層**：v2.14 引入 Slot 契約時，未全面預料到 Base UI 1.0 版本對 `asChild` 的棄用傾向及向 `render` prop 模式的全面演進。
2. **作用域丟失**：在舊的 `asChild` 寫法中，某些組件（如 `Dialog.Trigger`）內部的語言翻譯函數 `t` 常因作用域隔離或 React 渲染週期問題而無法正確獲取。
3. **契約模糊**：Slot 契約僅定義了組件結構，未強制渲染執行器的傳遞模式，導致代碼生成時混合了多種不兼容的寫法。

## 🛠️ 修復路徑
1. **模式轉換**：全面將 `<Component asChild>` 替換為 `render` prop 模式：
   ```tsx
   <Dialog.Popup render={(props) => <motion.div {...props} />}>
   ```
2. **顯式語言綁定**：通過 `createTranslate(lang)` 獲取具名翻譯函數 `translate`，並在 `render` prop 的閉包中顯式消費，確保作用域穩定。
3. **Prop 淨化**：在 `render` prop 中解構並過濾掉 `asChild` 等內置屬性，防止其透傳至不支持的原生 DOM 元素。

## 🛡️ 探針盲區與建議
- **現有盲區**：Diagnostics 僅涵蓋了數據一致性與基本的元件尺寸，缺乏對第三方庫 API 合規性的運行時掃描。
- **建議探針**：新增 `componentStructureGuard` 探針，掃描關鍵組件樹是否包含不推薦的 `asChild` 屬性，並驗證 `render` 回調的執行完整度。
